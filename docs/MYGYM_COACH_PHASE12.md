# myGym 教练优化：中文名称与独立问答

## 已实现的用户行为

- 教练的动作卡片、修改标题和变化说明复用动作库的名称函数，支持中文、个人改名、自建名称及原有英文名称偏好。
- 发给供应商的中文上下文包含已知动作的中文/个人名称和英文原名，动作 ID 保持不变。所有模型共用同一份生成数据和提示词。
- 输入框新增“训练问答 / 调整计划”选项，默认训练问答。询问动作、组数依据或替代动作时，不会直接进入计划生成或审查。
- 问答提示词要求直接解释，缺少器械、具体动作或限制条件时先追问，最多两个问题。明确希望改计划时提示选择调整计划模式。
- “调整计划”模式以及原有生成、复盘、审查快捷入口保留提案、确认应用、撤销与历史记录流程。
- 问答可参考当前计划、现有最多六条近期对话，以及待确认计划/审查摘要；明确区分提案和已应用内容。没有新增无限聊天记忆。

## 保护机制

新增 question 任务及 POST /api/coach/question。移动端自带密钥和服务器队列共用同一问答提示词、解析与严格输出校验。问答输出只允许 coach_contract=1 和不超过 3000 字符的 answer；夹带 changes、routines 或其他字段会被拒绝，并最多进入原有的一次修复。

问答复用现有身份、授权同意、供应商凭据、并发和每日次数限制。回答作为文字显示，不会进入应用计划函数，不会清空或替换待确认提案。训练记录、动作 ID、重量递进规则和持久化格式保持原有逻辑。

上下文仍按字段白名单构建，个人改名有长度上限；待确认审查只提供有界摘要和理由，不直接传递整个状态。密钥不会进入训练数据或问题上下文。

## 范围和限制

本次完成阶段 1、2；不新增阶段 3 的长期个性化记忆或阶段 4 的候选动作排序。现有语言包不包含的名称仍会回退原名；英文名称偏好继续生效。历史聊天原文不批量改写。模型解释是否自然、是否总能遵循语言要求，需要使用实际账户和模型继续验收，不能由模拟响应证明。

问答与计划模式由用户显式选择，以免含糊语句被误认为修改指令；并非实现了自动识别所有自然语言意图的分类器。公开 demo 无真实供应商时会提示先配置，不伪造真实回答。

浏览器与手机的原生能力差异仍存在。源码改动不会自动更新已安装 APK；服务端配对模式使用问答前也需要部署包含新接口的后端。
